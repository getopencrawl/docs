## Get the release kit

Download and unpack the `opencrawl-selfhost-<version>.tgz` kit from a stable [Helm release](https://github.com/getopencrawl/opencrawl-core/releases?q=helm-v&expanded=true). It includes the charts and pins the runtime image. Use Node.js 24 or later, Helm 3, and kubectl.

Choose a cluster with a default dynamic StorageClass and a CNI that enforces NetworkPolicy. Use a dedicated namespace. For remote access, configure DNS and HTTPS ingress for your workspace URL.

## Install and verify

In the unpacked kit, create `instance.json` with your kubectl context, namespace and URL.

```json
{
  "context": "my-cluster",
  "namespace": "opencrawl",
  "url": "https://opencrawl.example.com"
}
```

1. **Preview** with `node install.mts --config instance.json`. This prints the plan offline.
2. **Install** with `node install.mts --config instance.json --apply`.
3. **Verify** with `node verify.mts --config instance.json` to check the running application.

Retrieve `OPENCRAWL_SETUP_TOKEN` from the `<release>-runtime-credentials` Secret and open `/auth/signup?setup=TOKEN` at your workspace origin to create the first administrator. Treat that link as a secret. Keep the generated `.opencrawl-helm/` directory private.

## Choose services

The kit bundles PostgreSQL, OpenSearch, Temporal, S3-compatible storage and Airbyte. For capture without connected sources, set `airbyte.mode` to `disabled` in your config. To enroll unattended agents, follow [Machine API keys](/self-hosting/machine-keys/). To use services you already operate, start with the kit’s mixed or external examples and create their referenced Secrets in the installation namespace.
